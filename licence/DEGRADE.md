ES 9.5.6 build in the local image, 1 node, 1 GB heap, 3 GB container, t2-dev (48 CPUs, shared host, load 5 to 27), stub embedder (8 and 64 dims, no model),

Licence behaviour measured (E1): `start_trial?acknowledge=true` on a Basic node returns `trial_was_started:true`. Without `acknowledge=true` it returns HTTP 200 with
`trial_was_started:false` and an acknowledgement text. A second `start_trial` after any trial returns HTTP 403, `trial_was_started:false`, "Trial was already activated" (5 of 5 lives);
`GET /_license/trial_status` then says `eligible_to_start_trial:false`. `start_basic` without `acknowledge=true` returns 200 with `basic_was_started:false` and lists the
features that will be dropped (security, ml, inference, esql, watcher, ...); with it the node is Basic at once and the licence uid changes. The effect of `start_basic` is
already in force when the response arrives. Per-probe start times in `down_7` (five licensed probes: rrf, linear, semantic query, inference use, DLS search, plus the 4-thread control arm; not every feature): the control arm's first licence refusal began 18 ms before the response returned and its
last success 24 ms before; no probe that started after the response succeeded (0 of 5 probes, 494 polls). The poll figures of lives 1 to 5 (first refusal 0.007 to 0.303 s "after the response") are upper bounds set by the
poller's 0.1 to 0.2 s iteration (they are stamped at the end of a seven-request iteration), not a propagation delay. The first success after `start_trial` was seen 0.2 to 0.58 s after the response in the same upper-bound sense.

## Migration recipe to a Basic-safe mapping (proved in E3, every life)

1. **Float-source index (bbq_disk) to `hnsw` or `bbq_hnsw`.** Scroll the source with `_source: {"exclude_vectors": false}` (Elasticsearch 9 omits dense_vector from `_source` by default), bulk the documents into an index whose `dense_vector.index_options.type` is `hnsw` (or `bbq_hnsw`). Result in 5 of 5 lives: 299 of 299 documents (one was deleted during the run), 0 element-wise vector mismatches (float32 as returned by the node), vectors within 1e-6 of the stub's ground truth, kNN self top-1 100 of 100; target passes update, delete, force merge, index new.
2. **semantic_text to `text` plus `dense_vector`.** Scroll with `_source: ["title","tag","body","_inference_fields"]`, copy the single stored chunk embedding (`_inference_fields.body.inference.chunks.body[0].embeddings`) into a `dense_vector` next to the text. Result: 199 of 199 documents, 0 mismatches against the stored embeddings, within 0.002 absolute and cosine at least 0.99999 of the stub's float vectors (stored embeddings are rounded), kNN self top-1 100 of 100. Documents with more than one chunk are skipped and counted (0 here); multi-chunk text would need re-embedding outside Elasticsearch.
3. **Controls.** The plain index migrates with 0 changes (300 of 300). A migration with one vector perturbed by 0.01 is caught: exactly 1 mismatch against the true source.
4. Do not use `_reindex` or `update_by_query` for the licensed indices on Basic: both return 403 with every item failed.

## What is not covered (NOT TESTED)

- Licence returning on the same node after a downgrade (a trial cannot be restarted; no paid licence file). Recovery was proved only as Basic to trial on a fresh node (E2U) and by restart; DLS roles and inference endpoints surviving a downgrade and an upgrade are untested.
- Trial expiry by the clock (status `expired`); the Elasticsearch deprecation of an expired trial may differ from `start_basic` (unit-level only).
- A real rerank or embedding model run; `text_similarity_reranker` was only checked at the licence gate. Agent Builder and Kibana features: not exercised.
- Multi-node clusters, TLS on HTTP, and licence changes during a rolling restart.
- Document counts above 1,500 per read index and above about 600 requests per second.

## Findings outside the licence question (found while building the harness)

- **The reviewed adapter's `http_util.urlopen` builds an opener per call, which loads the system CA store each time** (cProfile: 30 calls, 0.625 s in `ssl.SSLContext.set_default_verify_paths`, 21 ms per request of GIL-held CPU). One process is capped near 45 requests/s, and 16 threads see 0.46 s latency per request against 7 ms raw. The workload patches the opener (one cached no-redirect opener) and says so in every result; the licence latch, fusion and request shapes are the reviewed code unchanged. Unpatched smoke life: 1,281 requests in 45 s.
- **Adapter probe cost on Basic**: while latched, the adapter sends one licensed probe (a 403) per `probe_ttl_s`; with the default 300 s that is one refused request every five minutes per adapter instance. Latch timeline of a Basic life showed the false/None/false cycle every TTL.
- **`_bulk` on a licence-refused field returns HTTP 200** with `errors:true`; only item results carry the 403. `memcore` `bulk_add` checks `errors`; any other client must.
- **`backend_fusion="linear"` falls back to RRF** on Basic: a different ranking function with no error and the same label (60 of 60 queries changed).
- **DLS fails closed with a message that does not mention the licence** ("unauthorized for user"): operators will not see the cause in the error.
- Thresholds disclosure: the first THRESHOLDS.md was written after one exploratory trial-to-Basic flip on a throw-away node (see addendum B).
