## Migration recipe to a Basic-safe mapping (measured in E3 in 7 lives; the completeness steps below were added after review-2 and have not run against a live node)

1. **Float-source index (bbq_disk) to `hnsw` or `bbq_hnsw`.** Scroll the source with `_source: {"exclude_vectors": false}` (Elasticsearch 9 omits dense_vector from `_source` by default), bulk the documents into an index whose `dense_vector.index_options.type` is `hnsw` (or `bbq_hnsw`). Result in 5 of 5 lives: 299 of 299 documents (one was deleted during the run), 0 element-wise vector mismatches (float32 as returned by the node), vectors within 1e-6 of the stub's ground truth, kNN self top-1 100 of 100; target passes update, delete, force merge, index new.
2. **semantic_text to `text` plus `dense_vector`.** Scroll with `_source: ["title","tag","body","_inference_fields"]`, copy the single stored chunk embedding (`_inference_fields.body.inference.chunks.body[0].embeddings`) into a `dense_vector` next to the text. Result: 199 of 199 documents, 0 mismatches against the stored embeddings, within 0.002 absolute and cosine at least 0.99999 of the stub's float vectors (stored embeddings are rounded), kNN self top-1 100 of 100. Documents with more than one chunk are skipped and counted (0 here); multi-chunk text would need re-embedding outside Elasticsearch.
3. **Controls.** The plain index migrates with 0 changes (300 of 300). A migration with one vector perturbed by 0.01 is caught: exactly 1 mismatch against the true source.
4. **Completeness before and during any migration (review-2 F4).** Take the expected document count from `_count` on the source, not from the scroll, after a refresh; require HTTP 200 and zero shard failures on both the refresh and the count, and keep the source free of writes until the scroll is done (the requests share no snapshot). Treat any non-200 scroll page, `timed_out: true`, failed shards or a duplicate id as an error and stop before writing. Continue each page with the latest `_scroll_id`. Require the collected ids to equal the expected count, and check the destination count and ids against that same figure. A migration that stops early without raising copies only part of the data and would verify against itself. In the recorded lives the source counts (299 and 199) equal the independent `_count`.
5. Do not use `_reindex` or `update_by_query` for the licensed indices on Basic: both return 403 with every item failed.

- **Gate coverage (gate reviews 5 to 7, F6 to F12): verdicts over typed evidence.** Gate reviews 2 to 7 each found the next unchecked condition in the same verdict code. The fix is a redesign, described in DESIGN-VERDICTS.md (scenario list, research, design):
  - `evidence.py` parses each life once into immutable evidence objects. Every leaf has a typed domain: finite values, integer counts ≥ 0, observed counts ≥ 1, rates in [0, 1], signed offsets only where stated. Every cross-field relation is declared and checked: numerator ≤ denominator, parts summing to the total, a stored derived rate equal to its counts, a flip no earlier than the transition request, failure windows consistent with the failure figures.
  - HTTP statuses become a closed set of outcome cases, and only a 403 is ever a refusal. Rates exist only as proportions of counts; a stored rate is checked against its counts and then dropped.
  - The constructors enforce every domain, control and relation, so an out-of-domain evidence object cannot be built by any route.
  - A control is a type that cannot be built without its sample.
  - Fixed key sets (5 probes, 12 battery paths, 2 indices × 4 operations) are one field per key.
  - `verdicts.py` judges only those objects. Evidence that does not parse is UNVERIFIED with the parse reason, which reports carry as `<gate>_reason`.
  - `lib.classify`, which the matrix cells use, maps through the same outcome cases. A 1xx or 3xx is no longer AVAILABLE.
  - Tests:
    - `tests/test_evidence.py` holds one regression per scenario.
    - A generator builds invalid evidence from the type definitions: every leaf mutated across its domain, every relation broken inside the fields' own domains, every outcome case other than the intended one, and emptied containers. Over 2,000 generated cases; none may PASS or raise, and the healthy fixture passes.
    - A structural test confirms each verdict takes exactly one evidence object and that `verdicts.py` never subscripts life data or compares a bare HTTP status.
  - Differential on invalid inputs, run against 4761862's gate-table summarizer: 2,349 generated cases, 0 loosened (old non-PASS, new PASS), 197 tightened, 2,152 the same.
  - The one optional field is `exp2.writes.sem_failed_other` (addendum D): when it is absent, EXP2-T4 passes only if `sem_failed` is 0.
  - Figures still trusted because the file holds no underlying counts are listed in DESIGN-VERDICTS.md section 5.
  - The aggregate `all_status[T1..T5]` covers the EXP2 gates only. It is UNVERIFIED when either direction has no complete life. Otherwise it is FAIL if any life fails, else UNVERIFIED if any life is not PASS, else PASS. An empty campaign is UNVERIFIED.

## Findings outside the licence question (found while building the harness)

- **The reviewed adapter's `http_util.urlopen` builds an opener per call, which loads the system CA store each time** (cProfile: 30 calls, 0.625 s in `ssl.SSLContext.set_default_verify_paths`, 21 ms per request of GIL-held CPU). One process is capped near 45 requests/s, and 16 threads see 0.46 s latency per request against 7 ms raw. The workload patches the opener (one cached no-redirect opener) and says so in every result; the licence latch, fusion and request shapes are the reviewed code unchanged. Unpatched smoke life: 1,281 requests in 45 s.
- **Adapter probe cost on Basic**: while latched, the adapter sends one licensed probe (a 403) per `probe_ttl_s`; with the default 300 s that is one refused request every five minutes per adapter instance. Latch timeline of a Basic life showed the false/None/false cycle every TTL.
- **`_bulk` returned HTTP 200 for the one-item bulk partial update on a `bbq_disk` index** (7 of 7 lives) while the item failed with the licence error `non-compliant for [bbq_disk]` (the response's `errors` flag was not stored; `failed=1` was). The initial 40-document bulk's HTTP status was not recorded (`matrix.py` kept only the item summary; it now records `bulk_http`, not rerun). A client must check item results, not the bulk HTTP status; `memcore` `bulk_add` is reported to check the `errors` flag (not re-verified here).
- **`backend_fusion="linear"` falls back to RRF** on Basic: a different ranking function with no error and the same label (60 of 60 queries changed).
- **DLS fails closed with a message that does not mention the licence** ("unauthorized for user"): operators will not see the cause in the error.
- Thresholds disclosure: the first THRESHOLDS.md was written after one exploratory trial-to-Basic flip on a throw-away node (see addendum B).
